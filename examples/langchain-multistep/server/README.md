# langchain-multistep — server

Express + LangChain agent server for the `langchain-multistep` example. The
Expo client (`../app`) talks to this server through the wireai-rn
`WebhookAdapter`. The server runs a 2-step LangChain workflow and returns
A2UI-compliant JSON that wireai-rn renders as native components.

## Setup

```bash
cd examples/langchain-multistep/server
cp .env.example .env
# Open .env, paste your OPENAI_API_KEY

yarn install         # or npm install
yarn dev             # starts on http://localhost:3000
```

Health check: `curl http://localhost:3000/health`.

## HTTP contract

The wireai-rn `WebhookAdapter` POSTs to a single endpoint:

```
POST /api/chat
Content-Type: application/json
x-wire-session-id: <opaque string>        # see "Session id" below
```

```json
{
  "messages": [
    { "role": "system",    "content": "...full A2UI system prompt..." },
    { "role": "user",      "content": "Ship a side project" },
    { "role": "assistant", "content": "..." }
  ],
  "model": "langchain-agent"
}
```

Response (always 200 with a wrapped envelope so the SDK never breaks):

```json
{
  "content": "{\"action\":\"render\",\"component\":\"StepList\",\"props\":{...}}"
}
```

The `content` string is a JSON-encoded A2UI envelope. wireai-rn parses and
validates it with `WireAIResponseSchema`. The server validates it *first*
with `zod` so a malformed LangChain emission never reaches the client — on
validation failure the server returns a `StatusCard` apology envelope
instead.

### Session id

The wireai-rn `WebhookAdapter` (v0.1.x) does not forward arbitrary headers.
This server supports two ways to deliver a stable session id:

1. **Header (preferred when calling directly):**
   `x-wire-session-id: <id>`
2. **Embedded marker (used by the Expo client):**
   the client puts `[wire-session:<id>]` into the system prompt suffix; the
   server greps it out of any system message.

Either path keys an in-memory `Map<sessionId, history>` so the workflow has
continuity across turns. The store is plain JS — restart the server and all
sessions reset (intentional for an example).

## How the conversation routes

The server treats the *number of user messages* as the turn counter:

| User-turn count | Server returns |
| --- | --- |
| 0 | `TextInputCard` asking for the user's goal |
| 1 | `SelectionCard` asking for the weekly time commitment |
| ≥ 2 | `StepList` generated by the LangChain workflow |

## How to debug the chain

- **LangSmith tracing.** Uncomment the `LANGCHAIN_*` env vars in `.env.example`,
  add your LangSmith key, restart. Every chain run shows up in your project.
- **Verbose chain logs.** Add `verbose: true` to the `ChatOpenAI` constructor
  in `src/chains/goal-plan.chain.ts` for token-level console output.
- **Inspect a single chain call.**
  ```bash
  curl -X POST http://localhost:3000/api/chat \
    -H 'content-type: application/json' \
    -H 'x-wire-session-id: dev-session' \
    -d '{
      "messages":[
        {"role":"system","content":"[wire-session:dev-session]"},
        {"role":"user","content":"Ship a writing app"},
        {"role":"user","content":"3 to 6 hours — one solid block per week"}
      ],
      "model":"langchain-agent"
    }'
  ```

## Common errors

| Symptom | Cause | Fix |
| --- | --- | --- |
| Every Turn-5 reply is a `StatusCard` saying *OPENAI_API_KEY is not set* | `.env` missing or not loaded | Copy `.env.example` to `.env`, set `OPENAI_API_KEY`, restart `yarn dev` |
| `StatusCard` saying *malformed JSON* | Model wrapped output in code fences or added prose | The server already strips ` ```json ``` ` fences. If it still trips, drop temperature in `goal-plan.chain.ts` |
| `StatusCard` saying *invalid A2UI envelope* | Model emitted the wrong component or extra fields | Tighten the system prompt in `goal-plan.chain.ts` or pin a better model in `.env` |
| Client can't reach the server from a physical device | `localhost` resolves to the phone, not your laptop | In the app's drawer Config Panel, swap the URL for your LAN IP (e.g. `http://192.168.1.20:3000/api/chat`) or use `ngrok http 3000` |
